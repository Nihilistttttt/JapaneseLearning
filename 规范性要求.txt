CodeArts 规范性要求
====================

【Git操作】
1. 禁止未经允许执行 git commit 或 git push，只有用户明确说"提交""推送"时才可执行
2. commit message 要讲清楚改了什么、为什么改，方便后续理解
3. 优化清单中已完成项打勾标记

【代码修改】
4. 修改前必须先完整阅读相关代码，严谨模拟逻辑链路后再动手
5. 不能仅凭静态分析下结论，必须结合实际运行行为验证（用户会实测）
6. 删除代码前必须确认无外部引用，且理解删除后对运行时行为的影响
7. 修复Bug时不能引入新的逻辑矛盾，必须推演修复后的完整执行路径

【分析要求】
8. 分析问题前先严谨模拟一遍逻辑，不能想当然
9. 评估严重性必须区分"理论风险"和"实际影响"，不能夸大
10. 对比方案时必须按以下要求执行：
    a. 明确界定每个方案的核心机制、关键参数与适用场景
    b. 构建完整的逻辑链路模拟流程，详细推演各环节的输入、处理逻辑与输出状态
    c. 从执行效率、资源开销、鲁棒性及容错能力等维度深度对比
    d. 梳理并评估逻辑链路中潜在的性能瓶颈与单点故障风险
11. 发现之前的分析有误时必须主动纠正，不能将错就错

【沟通风格】
12. 使用简体中文交流，混合英文技术术语（如VP2、Room、LiveData等）
13. 偏好通俗易懂的解释方式，避免过于晦涩的技术术语
14. 回答简洁，不说废话

【项目相关】
15. 切换单词通过底部按钮，不是滑动操作
16. ViewPager2Navigation的字段命名：overviewDetailVp2(中层)、meaningVp2(内层)，不与View层级混淆
17. 项目技术栈：Java 8 + MVVM + Room + ViewPager2，Python数据处理脚本
